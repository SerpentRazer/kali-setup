The user chose KDE Plasma over an Xfce+picom route specifically because **only KDE can blur the panel** — Xfce's panel does transparency but not blur. That was the deciding trade-off; don't relitigate it.

Hybrid Intel UHD (TigerLake GT1) + RTX 3060 Mobile with nvidia-driver 550 in offload mode; KWin composites on the **Intel** GPU, which is the stable choice. Stay on **Plasma (X11)** — Wayland on this Optimus setup is where tearing and blur artefacts concentrate.

Hard-won gotchas from that pass: **plasmashell rewrites `plasma-org.kde.plasma.desktop-appletsrc` on exit**, so `AppletOrder` edits only stick if you `kquitapp6 plasmashell` first, edit, then relaunch. `kpackagetool6 -t Plasma/Applet -s` gives false negatives for built-in applets (kickoff/kicker live as `.so` in `/usr/lib/x86_64-linux-gnu/qt6/plugins/plasma/applets/`) — check that path instead. `kickerdash` is NOT installed. The `linechart` sensor face draws no legend text in a panel (compact rep only draws the curve) — use `org.kde.ksysguard.textonly` for readable values. In BlurGlassyKvantum, `#414c52` is *only* small indicator glyphs (checkbox ticks, spin arrows, 8x2/2x8 rects), so it must be light on a dark theme; `reduce_menu_opacity=70` is what makes context menus unreadable (set ~12), and `reduce_window_opacity=70` is what gives the liked glass look — don't lower it.

Kvantum changes only apply to **newly started** apps, so verifying with an already-open window shows stale styling; `konsole` alone reuses the running process (needs `--separate`, which may open on another virtual desktop and evade screenshot capture).

2026-08-09 third pass — fixed unreadable text everywhere. The CyberGlass fork changed `[GeneralColors]` to dark but left every **per-widget** `text.*.color` at the light theme's values, so menus/menubar/toolbar/tabs/titlebar/combobox drew near-black (`#000000`, `#313334`) glyphs on the dark glass. Fix: sweep the whole kvconfig — `#000000`→`#cfefff`, `#313334`→`#cfefff`, `#3daee9`/`#007e8c`/`#005a64`→`#00e5ff`, and the two `#ffffff` press/toggle in `[Toolbar]`→`#00e5ff`. Only `highlight.text.color` and `progress.indicator.text.color` should stay dark (`#080c14`) — they sit on cyan. Rule: after recolouring `[GeneralColors]`, always `grep -n 'text\..*color=#'` and check nothing dark survives. Kvantum picks up kvconfig edits **live** (no app restart needed), unlike SVG changes.

Same pass, three more findings: (a) the **desktop** right-click menu is drawn by plasmashell, so Kvantum/Plasma-theme fixes don't reach it until `kquitapp6 plasmashell` + `kstart plasmashell`; (b) `~/.config/plasmarc` had **no `[Theme]` section**, leaving the Plasma desktop theme at `default` (Breeze *light*) under a dark colour scheme — fixed with `plasma-apply-desktoptheme breeze-dark`; (c) kdeglobals had **no `[Icons]` section** at all, so folder/app icons fell back to bare hicolor — fixed with `/usr/lib/x86_64-linux-gnu/libexec/plasma-changeicons Flat-Remix-Blue-Dark` (Kali's native set; `Flat-Remix-Teal-Dark` is the more on-theme cyan option). Also confirmed empirically: Kvantum genuinely does **not** live-reload into running apps — a fresh `konsole --separate` showed correct light menu text while the long-running one stayed black.

2026-08-09 fourth pass — the two remaining complaints, both fixed. (a) **Mirroring returned on every restart** because the *saved* two-output profile `~/.local/share/kscreen/d762afe030de15b2f76e1b2dd914cc3a` still had both outputs at `pos {0,0}` — the earlier live `kscreen-doctor` extend had never been written back, so kded's kscreen module faithfully restored the duplicate at each login. There is no `kded6rc`, so the kscreen module autoloads by default (confirmed present in `qdbus6 org.kde.kded6 /kded loadedModules`); the `autoload=false` in `kded5rc` is only `device_automounter` and is unrelated.

(b) **Folders opened from the desktop looked unthemed** because `~/.config/mimeapps.list` still had `inode/directory=thunar.desktop` left over from Xfce — the desktop folder-view honours the XDG default, so it launched GTK Thunar (unstyled by Kvantum) while launching Dolphin by hand looked right. General rule for this box: Xfce is still installed, so any "this one app ignores the theme" report is probably an Xfce/GTK default lingering in mimeapps.list — check `xdg-mime query default <type>` before touching theme config.

**Correction (2026-08-09, fifth pass): the textonly face DOES support custom sensor labels** — the earlier note here was wrong. `CompactRepresentation.qml` does `name: root.controller.sensorLabels[modelData] || sensor.name`, and the config key is `SensorLabels`, stored as its own group in exactly the same shape as the existing `SensorColors` group: `[Containments][2][Applets][<id>][Configuration][SensorLabels]` with `cpu/all/usage=CPU`. (Found by `strings` on `libKSysGuardSensorFaces.so.2`, where `SensorLabels` sits adjacent to `SensorColors`.) Applied: CPU / MEM / ↓ / ↑. Also note the panel widget uses **CompactRepresentation, which never reads `showLegend` or `title` at all** — those only affect the click-through popup, so toggling them to tidy the panel does nothing (I tried; it changed nothing visible). To narrow a sensor widget, change the *sensor*: `memory/physical/usedPercent` is much narrower than `memory/physical/used`, because `LegendDelegate` reserves width via `Formatter.maximumLength(unit)` for the widest possible value of that unit, not the current one. Pager `displayedText` is an Enum accepting `Number`/`Name`/`None` (schema lives inside `/usr/lib/x86_64-linux-gnu/qt6/plugins/plasma/applets/org.kde.plasma.pager.so` — it's a built-in `.so`, not a QML plasmoid dir); set to `None` to kill the chunky numbered blocks. Note Konsole transparency is *not* a Kvantum effect — it lives in the colorscheme's `Opacity`, so it must be set separately.

**Pager sizing (fifth pass, took three attempts — read this before touching it again).** The pager has **no width, scale, or size setting** in its schema; each desktop cell is a screen-aspect rectangle scaled to fill the panel height, so on the 46px panel two desktops at `Rows=1` cost ~275px of taskbar. What does *not* work: `pagerLayout=Vertical` — the key exists in the kcfg (`Default`/`Horizontal`/`Vertical`) and writes cleanly, but the widget **ignores it in a horizontal panel**; verified by screenshot, no visible change. What works: **KWin `[Desktops] Rows`**, because the pager just mirrors KWin's grid. `Rows=2` with 2 desktops makes it one column of two ~23px cells, ~41px total — roughly a sixth the width. Apply with `kwriteconfig6 --file kwinrc --group Desktops --key Rows 2` + `qdbus6 org.kde.KWin /KWin reconfigure`, then restart plasmashell to re-layout. Side effect: desktop switching becomes vertical (`Ctrl+Alt+↑/↓`, not `←/→`); `Ctrl+F1`/`F2` unaffected.

Other fifth-pass panel changes: clock `customDateFormat` → `yyyy-MM-dd` (ISO, reads like a log timestamp); added `org.kde.plasma.marginsseparator` as applet id 30 between the spacer and the sensor cluster; `AppletOrder=3;4;5;26;30;27;28;29;6;7;19;20`. Panel config backup from before this pass: `scratchpad/appletsrc.bak`. Open nit: MEM truncates to `M…` at its current width.

Icons are now **Flat-Remix-Teal-Dark** (chosen over Flat-Remix-Pink-Dark and a Papirus install). It's an overlay theme — it only ships `places` + `apps` and `Inherits=Flat-Remix-Blue-Dark`, so folders go cyan and nothing else moves. `plasma-changeicons` also rewrites all three GTK configs (`gtk-3.0`, `gtk-4.0`, `.gtkrc-2.0`) itself, so GTK apps stay in sync with no extra work. Its `kf.iconthemes: Icon theme "elementary"/"AdwaitaLegacy" not found` warnings are harmless — declared fallbacks Kali doesn't ship. `papirus-folders` is **not** packaged in Kali, so cyan Papirus folders would need the GitHub script or hand-symlinking.

Wallpaper: the user installed the KDE Store addon **ASCII Wallpaper by korvexx** (`~/.local/share/plasma/wallpapers/de.korvexx.ascii_wallpaper/`). It's a live GPU shader that ASCII-ifies a source image — it does **not** export image files. Config keys in `contents/config/main.xml`: `Mode` (Image/Slideshow), `Detail` where the naming is inverted (`0`=2x4 finest, `1`=4x8 default, `2`=8x16 chunkiest), `AsciiChars` (editable dark→bright ramp), `FontFamily` (monospace only), `Grayscale`, `SlideInterval`. With Grayscale off it samples the source image's colours, so on-palette output means feeding it an already cyan/magenta, high-contrast, mostly-black source. The user asked how to use it and I offered to generate matching 1920x1080 source images — **offer not yet taken up**.

2026-08-09 sixth pass — **Yakuake** added as the drop-down terminal (chosen over kitty/alacritty because Konsole-based terminals are the only ones whose *chrome* Kvantum themes; kitty draws its own widgets). Key facts: yakuake has **no profile setting of its own** — it inherits `DefaultProfile` from konsolerc, so CyberGlass came along for free. Translucency is `[Appearance] Translucency=true` in `~/.config/yakuakerc` and requires a skin that supports it (`default` does; skins live in `/usr/share/yakuake/skins/`). F12 is yakuake's **built-in default** — KGlobalAccel writes `[yakuake] toggle-window-state=F12` into `kglobalshortcutsrc` on first launch, and hand-writing that group *before* the first run gets clobbered, so always launch once then read it back. No plain-F12 conflict existed (only `Alt+Shift+F12` suspend-compositing and `Ctrl+F12` show-dashboard). Blur confirmed by `xprop -id <win> _KDE_NET_WM_BLUR_BEHIND_REGION` returning the property **set with an empty value** — that's KWin's "blur the whole window", not a failure. Autostart via copying `/usr/share/applications/org.kde.yakuake.desktop` into `~/.config/autostart/`, needed because the F12 binding only lives as long as the process.

Background must live somewhere the `sddm` user can read (`/usr/share/wallpapers/`, 0644 root:root) — not `~/Pictures`. Plymouth: forked the stock `kali` script theme to `cyberglass` and luminance-mapped its PNGs with `magick f.png -colorspace gray +level-colors "#080c14","#00e5ff"` (preserves alpha; the fade layer got magenta). **`plymouth-set-default-theme` alone is not enough — without `update-initramfs -u` the theme isn't in the initrd and boot silently falls back, with no warning.** Confirm with `lsinitramfs /boot/initrd.img-* | grep -c plymouth/themes/cyberglass`.

Same pass, shell identity (**user later narrowed scope to login+boot only, so these may be reverted** — backup at `scratchpad/zshrc.bak`): Kali's stock zsh prompt recoloured blue/green→`#00e5ff`/`#ff2bd1` in `~/.zshrc`; zsh 5.9 emits real 24-bit escapes so `%F{#00e5ff}` works directly.
